# Documentation Rules

## Objetivo

Definir los estándares para la creación, mantenimiento y actualización de la documentación del proyecto.

---

# Principios

La documentación debe ser:

- Clara.
- Actualizada.
- Consistente.
- Trazable.
- Comprensible.

---

# Formato

Todos los documentos deberán utilizar:

- Markdown (.md)
- Tablas Markdown
- Diagramas Draw.io
- UML cuando corresponda

---

# Convenciones de Nombres

## Archivos

Formato:

nombre-descriptivo.md

Ejemplos:

functional.md
authentication.md
testing-strategy.md

---

# Diagramas

Todo diagrama debe tener:

## Fuente Editable

Ubicación:

08-uml/source

## Exportación

Ubicación:

08-uml/exports

---

# Actualización

Cuando se modifique:

- Arquitectura.
- Modelo de datos.
- APIs.
- Requisitos.

La documentación relacionada deberá actualizarse.

---

# Control de Cambios

Toda modificación debe realizarse mediante:

- Branch
- Pull Request
- Revisión

---

# Responsabilidades

Cada integrante es responsable de mantener actualizada la documentación de los componentes que desarrolla.
