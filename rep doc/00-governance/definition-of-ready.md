# Definition of Ready (DoR)

## Propósito

La Definition of Ready establece las condiciones mínimas que debe cumplir una historia de usuario o requerimiento antes de ser asignado para desarrollo.

---

# Objetivos

- Reducir incertidumbre.
- Evitar retrabajo.
- Mejorar planificación.
- Facilitar estimaciones.

---

# Información Mínima Requerida

Todo requerimiento debe contener:

## Identificador

Ejemplo:

HU-001

---

## Título

Nombre corto y descriptivo.

Ejemplo:

Registrar Instructor.

---

## Descripción

Explicación clara del objetivo.

---

## Actor

Persona o rol que utilizará la funcionalidad.

Ejemplo:

- Administrador
- Coordinador Académico

---

## Criterios de Aceptación

Deben ser verificables.

Ejemplo:

- El sistema valida documento único.
- El sistema valida correo único.

---

# Dependencias

Deben estar identificadas:

- Técnicas.
- Funcionales.
- Infraestructura.

---

# Diseño

Debe existir:

* Wireframe.
* Mockup.
* Diagrama de flujo.

Cuando aplique.

---

# Datos Necesarios

Se deben conocer:

* Entradas.
* Salidas.
* Restricciones.

---

# Checklist

* [ ] Descripción completa
* [ ] Actor identificado
* [ ] Criterios definidos
* [ ] Dependencias identificadas
* [ ] Diseño disponible
* [ ] Lista para desarrollo
